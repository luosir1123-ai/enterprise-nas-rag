# 扫描结果说明

## 扫描完成后会得到什么

运行 `scripts/scan_nas.py` 后，第一版会生成三个文件：

- `data/inventory/file_inventory.csv`
- `data/inventory/file_inventory.sqlite3`
- `data/inventory/summary.md`

## 这三个文件分别有什么用

### 1. `file_inventory.csv`

这是最重要的清单文件。每一行代表一个文件，字段包括：

- 知识库名称
- 知识库 ID
- NAS 路径
- 扫描路径
- 相对路径
- 文件名
- 扩展名
- 文件大小
- 修改时间
- 哈希值
- 是否候选文件
- 排除原因
- 解析状态
- 权限组

用途：后面抽样、解析、评估、检索过滤都依赖它。

### 2. `file_inventory.sqlite3`

这是结构化版本，方便后面用 SQL 做统计、筛选和增量比对。

用途：

- 看某个知识库的候选文件数量
- 看某种扩展名的文件分布
- 看最近修改的文件
- 做重复扫描比对

### 3. `summary.md`

这是给人看的中文汇总。

用途：

- 快速看每个知识库的总大小
- 快速看文件数
- 快速看 Office / PDF / 图片 / 扫描件分布
- 快速看 Top 大文件
- 快速看最近一年文件数量

## 如何判断扫描是否正常

### 正常情况

- 三个知识库都能扫到文件
- 候选文件数量大于 0
- 排除文件数量和实际目录情况一致
- `summary.md` 里的统计和目录规模大致匹配
- 重复运行时，文件数量和哈希结果稳定

### 异常情况

- 扫描路径不存在
- 候选文件数是 0
- 所有文件都被排除
- `summary.md` 里某个知识库没有统计数据
- 重复扫描结果明显变化，但目录没有改动

## 这一步的判断意义

扫描不是为了直接回答问题，而是为了先确认：

1. 三个目录真的接进来了
2. 文件结构真的被看见了
3. 排除规则没有把所有文件误删掉
4. 后面抽样和评估有真实基础

## 下一步

如果扫描结果正常，再做样本计划和评估集。
如果扫描结果不正常，先修挂载、权限或配置，不要直接往问答层走。
