# 三目录只读挂载方式决策说明

## 结论

第一版优先用 **SMB 只读挂载**，只有在 NAS 明确已经稳定启用 NFS、并且你更习惯 Linux 原生挂载时，才考虑 NFS。

## 为什么优先 SMB

1. Synology 上 SMB 通常更容易直接对接共享文件夹和账号权限。
2. Windows、Linux、后续外部服务器都能用同一套共享名思路。
3. 只读账号 `rag_reader` 的权限验证更直观。
4. 出问题时更容易从“共享名、账号、权限、协议版本”四个点排查。

## 为什么不优先 NFS

1. NFS 在 DSM 侧和 Linux 侧都更依赖细节配置。
2. 共享路径、导出规则、UID/GID 映射更容易引发排查成本。
3. 如果团队后面还有 Windows 临时测试，SMB 更统一。

## 推荐操作原则

- NAS 原始目录只作为共享源。
- 外部服务器只做只读挂载。
- 优先使用 `rag_reader`。
- 不使用 QuickConnect 做索引通道。
- 先挂三个目录，不扩展到全 NAS。

## 如果选择 SMB，检查顺序

1. DSM 里确认 SMB 已启用。
2. 确认共享名就是三个业务目录。
3. 确认 `rag_reader` 对三个共享只有只读权限。
4. 在 Ubuntu 服务器安装 `cifs-utils`。
5. 用只读参数挂载到 `/mnt/nas/...`。

## 如果选择 NFS，检查顺序

1. DSM 里确认 NFS 已启用。
2. 确认导出规则只允许服务器访问。
3. 确认导出的是三个共享目录，不是整块卷。
4. 在 Ubuntu 服务器安装 `nfs-common`。
5. 用只读参数挂载到 `/mnt/nas/...`。

## 实际建议

如果现在只是为了把 RAG 试点尽快跑起来，先走 SMB。
如果后面确定这台 Ubuntu 服务器会长期承担索引任务，再评估是否改成 NFS 或保留 SMB。
