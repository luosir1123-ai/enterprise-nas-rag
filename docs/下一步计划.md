## 2. 目前还没有完成什么

当前还没有完成的，是决定这个项目能不能真正跑起来的核心步骤：

- NAS 三目录的真实只读挂载
- 真实文件盘点和增量扫描
- 代表性样本抽取

- 检索服务的第一版上线
- 带来源引用和无证据拒答的闭环验证

也就是说，现在还停留在“项目准备齐全”，还没有进入“真实企业资料可检索”状态。

## 3. 为什么要这样推进

企业级 RAG 不应该先做一个能聊天的界面，而应该先把下面这条链路打通：

```text
NAS 原始目录
  -> 只读挂载
  -> 文件清单
  -> 样本抽取
  -> 人工评估集
  -> 文档解析
  -> 切片
  -> embedding
  -> 向量检索
  -> rerank
  -> 带引用回答
  -> 无证据拒答
```

这样推进的原因有三个：

1. 原始资料必须先被可靠接入
2. 权限必须先被控制住
3. 没有评估集，就无法判断答案到底有没有问题

如果先做问答界面，后面往往会出现“看起来能答，但其实不准”的情况。

## 4. 下一步要做的事情

### 第一步：在 Ubuntu 服务器上建立固定工作目录

建议在服务器上建立：

```text
~/enterprise-rag
```

这个目录后续会承载：

- 项目代码
- 配置文件
- 扫描结果
- 样本计划
- 评估集
- 日志
- 后续检索服务

这样做的原理很简单：把所有和企业 RAG 相关的东西收束到一个固定根目录，后续才方便部署、备份和维护。

### 第二步：把 NAS 三个目录只读挂载到服务器

建议固定挂载到：

```text
/mnt/nas/PUR-SHR
/mnt/nas/SALES-SHR
/mnt/nas/product-design
```

这样做的原理是：

- 脚本只需要面对固定路径
- 以后无论 NAS 内部怎么变，外部服务都只看这三个入口
- 只读挂载可以防止 RAG 流程误改原始资料

### 第三步：修改知识库配置，让扫描脚本指向真实挂载路径

把 `configs/knowledge_bases.yaml` 里的 `local_scan_path` 改成真实挂载路径。

这样做的原理是：

- 配置和代码分离
- 以后路径变化只改配置，不改程序
- 方便切换到测试路径、真实路径或备用路径

### 第四步：运行只读扫描，先生成清单，不直接做问答

运行 `scripts/scan_nas.py` 后，要先得到：

- `data/inventory/file_inventory.csv`
- `data/inventory/file_inventory.sqlite3`
- `data/inventory/summary.md`

这样做的原理是：

- 先把文件变成结构化清单
- 再决定哪些文件值得解析和索引
- 先看目录规模和文件类型分布，再决定后续资源投入

### 第五步：从三个知识库中抽样代表性文件

每个知识库先抽样 `100-300` 个文件，覆盖：

- Word
- Excel
- PPT
- PDF
- 最新文件
- 历史文件
- 命名混乱文件

这样做的原理是：

- 抽样不是为了省事，而是为了先验证代表性
- 真正企业数据通常很乱，必须覆盖“正常文件”和“边缘文件”
- 先做样本，才能知道解析和引用会不会出问题

### 第六步：建立人工评估集

每个知识库至少准备 `20-50` 条评估问题，并记录：

- `question`
- `expected_answer`
- `source_file`
- `source_section_or_page`
- `knowledge_base`
- `must_refuse_if_no_evidence`

这样做的原理是：

- 评估集是企业 RAG 的验收标准
- 没有评估集，就没有办法判断模型是真的会答，还是在乱猜
- 无法定位证据的问题必须标记为拒答，不允许模型编造

### 第七步：在服务器上部署第一版检索服务

第一版推荐技术栈保持简单、可维护：

- FastAPI
- PostgreSQL
- Qdrant
- 文档解析组件
- 中文 embedding
- reranker
- 外部 LLM API 或私有 LLM

检索顺序保持为：

```text
metadata filter -> vector search -> rerank -> cited answer -> low-confidence refusal
```

这样做的原理是：

- 先按权限和知识库过滤
- 再做向量检索
- 再重排
- 再生成带引用答案
- 证据不足时拒答

### 第八步：验证权限是否真的生效

必须在检索前先按以下字段过滤：

- `knowledge_base`
- `permission_group`

不能先检索再隐藏无权限结果。

这样做的原理是：

- 防止无权限内容进入候选集
- 防止模型“看见了但不展示”的泄露风险
- 权限控制必须发生在检索之前，而不是回答之后

## 5. 下一步的执行顺序

### 清单是否完成

- `file_inventory.csv` 成功生成
- `file_inventory.sqlite3` 成功生成
- `summary.md` 能输出中文统计

### 样本和评估是否完成

- 每个知识库都能抽出代表性样本
- 每个知识库都至少有 20 条评估问题
- 每条问题都能对应来源文件

### 检索服务是否完成

- 能返回来源路径
- 无证据时会拒答
- 无权限内容不会进入候选结果
